### CPUの仕様

なるべくレール数を少なくするため、ギリギリCPUと呼べなくもない(？)程度の、微妙なラインにしました。

- 4ビットレジスタ × 2(プログラムカウンタ、汎用レジスタ)
- メモリアドレス幅4ビット
- 命令長8ビット固定

列車は以下の経路を進みます。

1. プログラムカウンタ(PC)からアドレスを読む
2. プログラムメモリの読み込み
3. 命令のデコード
4. レジスタ操作
5. PCを更新(通常はインクリメント、JMP時はPCにXを代入)
6. 1へ

上部に並んでいる8個の同じパターンが、4ビットのプログラムカウンタと汎用レジスタです。それぞれを操作できますが、可能な操作は代入とインクリメントだけです。

レジスタは2つだけで、一方はプログラムカウンタに使うため、実用的な計算をするのは困難です。命令やレジスタは追加できる余地を残してあるので、レジスタを追加して加算命令などを追加すれば実用的な計算にも対応できます。

下部に並んでいるのはプログラムメモリで、8ビット単位で読み出すようになっています。アドレスが4ビットなので、16バイトまで接続できます。今回は8バイトだけ実装しました。

メモリの右側には命令デコーダ用の分岐ポイントが8ビット分並んでいます。代入とインクリメントだけなので、デコード自体はとても単純です。上部のレジスタの末尾にインクリメントがオーバーフローしたかを記憶する分岐ポイントがつながっています。

### 命令セット

| メモリ上の値 | 命令 | 動作 |
|---|---|---|
| 0000???? | NOP | 何もしません |
| 0100???? | INC | X += 1 |
| 1000abcd | JMP | PC := abcd |
| 1010abcd | JMP | PC := abcd if overflow == 1 |
| 1100???? | JMP | PC := X |
| 1110???? | JMP | PC := X if overflow == 1 |
| 1001abcd | LD | X := abcd |
| 1011abcd | LD | X := abcd if overflow == 1 |

`?` の値は無視されます。`abcd` は、`a` が MSB です。

`INC` 命令で `X` の値がオーバーフローすると0に戻ります。オーバーフロー時に `overflow` フラグは1になり、それ以外では0になります。

ジャンプ命令はPCへの代入として実装されていて、汎用レジスタについても条件付きで操作できます。

## プラレールのシミュレータを作る

CPUの設計やテストができそうなプラレールのレイアウトエディタやシミュレータが見つからなかったため、作成しました。ブラウザ上で動作します。
表示は簡易的で、サポートしているレールの種類は少ないですが、レイアウトを考えて列車の経路を確認する目的には使えると思います。

- https://binzume.github.io/plarail-sim/ ([GitHub](https://github.com/binzume/plarail-sim))

静的なHTMLとJavaScriptだけなので、リポジトリを clone して `index.html` を開くだけでも動作します。
この記事のCPUのレイアウトも `examples` フォルダ内にあります。

描画のパフォーマンスがあまり良くないため、1万レールを超えるレイアウトでは編集操作がもたつきます。複雑なレイアウトを快適に編集するには、以下の機能が有効です。

- Vキーを押すと、選択レールと未接続レール以外が一時的に非表示になります。編集したい範囲だけを表示できます
- 階層を分けて、1F、2F……のようにフィルタして表示します
- モジュールごとにレイアウトを作成し、複数ファイルをドロップまたは Shift＋ドロップしてレイアウトをマージします
- `cmds` 以下にあるコマンドラインシミュレータには、レール通過時にログを出す機能があります。プラレールのテストを書くのに便利です

## プラレール上で計算を行う

最近、「[自動ターンアウトレール](https://takaratomymall.jp/shop/g/g4904810150985/)」という便利なレールを知りました。これがあれば列車を走らせて計算できると思いましたが、プラレールで計算機を作りたいと夢見る人は世の中にたくさんいるので、探せば分かりやすい解説が見つかります。

以下のリンク先の説明がとても分かりやすいので、事前に読んでおくとプラレールの挙動が理解しやすいと思います。

- [プラレールで半加算器を設計した話](https://cybozushiki.cybozu.co.jp/articles/m001205.html)

### 基本素子

基本的には分岐ポイントを組み合わせて、必要な論理回路を組み立てます。
ただし、公式のレールだけでは複数の列車を同期させる仕組みが無さそうです。そのため、列車の速度に依存せず確実に動作させるには、1つの列車で一筆書きできる回路を設計する必要があります。

#### ポイント切り替え

ターンアウトレールや単線複線ポイントレールを使います。

プラレールの分岐ポイントは、分岐先側から列車が進入すると向きが切り替わるため、読み書き可能なレジスタとして使えます。

分岐の組み合わせによって0/1のどちらかのレールにたどり着くように線路を接続し、論理回路を作ります。

#### 自動ターンアウトレール

列車の向かう先を交互に振り分けたり、方向を固定したりする設定を持つレールです。

この自動ターンアウトレールには、もう1つ重要な特性があります。逆向きに進入しても、ポイントの状態が変わりません。一見なんてことのない性質ですが、通常の分岐ポイントでは(通常の使い方では)実現できません。

ただ、プラレールにはまったことがあるなら、通常の切り替えポイントの黄色いパーツを外して切り替わらないようにしたり、輪ゴムやテープなどで決めた状態に固定して使ったりしたことがある人も多いはずです(絶対に欲しくなるのに、なぜ製品化されていないのでしょう？)。

今回は、自動切り替え動作のものを赤、固定動作のものを緑のレールとして表示しています。

### プラレール論理回路

#### NAND

まずは基本のNANDゲートです。

2つの入力がともに1のときだけ出力が0になるNANDゲートがたくさんあれば、通常のコンピュータと同等の計算が可能です。

![image.png](https://qiita-image-store.s3.ap-northeast-1.amazonaws.com/0/58515/dc73fbca-a97f-47c6-9b6a-d6343b0746b0.png)

緑色のレールは切り替えポイントを固定し、逆側から列車が進入しても状態が変わらないようにしています。

左側の2つの入力列車が、それぞれ0または1のレールから進入すると、右側の列車が0または1のレールに到達するようになります。

上の画像では、左側の各入力の書き込みに使った列車を使い捨てる、富豪的な配置にしています。しかし実際には、回収用の分岐から列車を取り出して次の回路に向かわせ、1つの列車だけで動かす必要があります。

### 値の複製

電子回路なら配線をつなぐだけで信号を分岐させられますが、列車は分裂しないので、一筆書きで計算しなければなりません。そのため、NANDゲートだけでは回路の配線ができません。

![image.png](https://qiita-image-store.s3.ap-northeast-1.amazonaws.com/0/58515/c4b58a8b-dcf6-440e-88bf-a15d2187e862.png)

同じ分岐ポイントから2回読み出して、自動ターンアウトレールで1回目と2回目の行き先を変えています。

内部の切り替えポイントの初期状態を注意深く設定すれば、特殊なレールがなくても実現できます。しかし、状態を列車ではリセットできず一度しか使えないので、先ほどの半加算器の記事と同じ仕組みにしました。

### 複数箇所からの書き込み

読み出しと同様に、書き込み時にもすべての入力経路が合流し、列車自身はどこから来たのかを忘れてしまいます。
そのため、事前に列車がどこから来たのかをレールの状態で保持しておく必要があります。

その場合も、列車が向かうべき先を処理の出力側で読み取れるように、自動ターンアウトレールを使って出力レールの本数分だけ複製して保持しておきます。

## CPUを作る

プラレールで計算する方法が分かったので、CPUを作っていきます。

### プログラムメモリ

プログラムメモリは、ポイント切り替えレールを並べて実装します。
プログラムからの動的な書き換えはサポートしません。

![image.png](https://qiita-image-store.s3.ap-northeast-1.amazonaws.com/0/58515/f0a15076-9200-41cd-93bb-03fda0a561f3.png)

各ビットの0と1を2本のレールで表現し、8ビットで16本のレールをメモリバスとして扱います(画像内の縦向きのレール)。
レイアウトの左寄りに縦に並んでいる8個の分岐がプログラムを保持するレールで、一番上の分岐を LSB として、上から順番に格納します。

なるべく小さくするため、各ビットの読み出し用に自動ターンアウトレールをツリー状に並べています。
読み出しは1ビットずつ行いますが、アドレスは1バイト単位で指定し、同じアドレスを8回連続で読むと1命令分が読み込まれます。

上のレイアウトの場合、LSB = 1、MSB = 8として、1、5、3、7、2、6、4、8という順序で読み出されます。そのため、8ビット目に列車が来た時点で命令のデコードを始めるようになっています。

### レジスタの設計

上で述べた通り、レジスタの書き込み・読み出し経路数に比例して規模が大きくなるため、ファンイン・ファンアウト数をなるべく小さくする必要があります。そのため、レジスタに対する操作を考慮しながら、レジスタを構成する各ビットを設計します。

![image.png](https://qiita-image-store.s3.ap-northeast-1.amazonaws.com/0/58515/dfbc262c-e7c3-48da-b38c-57ce9b50d722.png)

1ビットあたり550レールくらいです。

インクリメントと値の転送だけサポートすることにして、レジスタの各ビットを以下のような構成にしました。

- `INC` レールから列車が進入すると、インクリメントされる
  - 繰り上がりがあれば `INC_NEXT` レールから列車が出てくるので上位ビットにつなげる
  - 繰り上がりがなければ `EXIT` レールから出てくるので、処理は終了
- 書き込み時は一度 `W_PREPARE` レールに列車を入れてから、`W_0` または `W_1` から入り直すと値が更新される
  - `W_PREPARE` を通らずに `W_0`、`W_1` に進入した場合は、何もせず `0`、`1` の出力レールから出てくる(複数レジスタを重ねておいて、任意のレジスタに書き込むことができます)
- 読み込み時は下側の `READ` レールに列車を入れると、`0`、`1` の出力レールから出てくる

今回は4ビットですが、並べれば任意のビット数に拡張できるように設計しています。
さらに縦に重ねれば任意のレジスタ間で値の転送ができるのでインクリメントと代入はこれを並べるだけで実装できます。


### CPUを組み立てる

最初の全体のレイアウトに戻ります。

直線レールの長さ216 mmを基準に換算すると、レイアウトの占有面積は約45 m × 45 mです。
厚みは3階層分しかないので、うまく折りたたんで縦に積み重ねれば小さくできます。お金と根気と広い場所があれば、なんとか作れる規模だと思います。

各ブロックはレールが衝突しないように坂レールで階層を分けていますが、モジュール間の接続は厳密ではないため、レールが重なっています。
折りたたんで高さ方向に積み重ねることで、せめて体育館サイズにするつもりだったのですが、レイアウトを俯瞰しにくくなるので広げたままにしています。

## 動作確認

ブラウザのシミュレータは最大16倍速まで速度を上げられますが、それでも時間がかかります。
なので、コマンドライン版のシミュレータでテストします。
インスペクタでレールのイベントに何か書いておくと、シミュレータ上でのレール通過時にログを出せます。

```
node cmds/simulate.js examples/cpu/cpu.json --speed 1000 --time 36000
```

速度の倍率とシミュレータ内での実行時間の制限(単位は秒なので、上の例では10時間)を指定できます。
サンプルはNOP命令が並んでいるだけなので、そのまま実行すると、メモリの読み込みとプログラムカウンタのインクリメントがログに出ます。

## 最後に

部屋の広さの都合で、残念ながら動作確認はシミュレータでしか行っていません。
現実的なレール数で4ビットコンピュータを作れそうなことが分かりましたが、1命令の実行に1時間以上かかるため、よほど暇でなければ実際のプラレールでは作らないと思います。

実行速度がネックなので、複数列車で並列処理したいのですが、公式のレールで列車間の同期を取ることができなさそうです。
複数列車を交互に発車させる駅があるので、列車がそろったら同時に発車する待ち合わせ駅もあれば、とても夢が広がるのですが……。
