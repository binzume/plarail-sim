数十年ぶりにプラレールで遊んでいて、コンピュータを作りたくなったので、簡単なCPUを設計してみました。

## CPUの仕様

なるべくレール数を少なくするため、ギリギリCPUと呼べなくもない（？）程度の、微妙なラインです。

- 4ビットレジスタ × 2（プログラムカウンタ、汎用レジスタ）
- メモリアドレス4ビット
- 命令長8ビット固定

### レイアウトの全体像

規模は約12,000レール、直線レールの長さ(216mm)基準でレイアウトの面積は約 35 m x 35 m ほどなので、お金と根気があれば、ギリギリ作れると思います。

![image.png](https://qiita-image-store.s3.ap-northeast-1.amazonaws.com/0/58515/757b10a1-2d4f-43e1-8cb1-dd051574bdab.png)

赤や緑で表示されているレールがありますが、後の説明に出てきます。

列車は以下の経路を進みます。

1. プログラムカウンタからアドレスを読む
2. プログラムメモリの読み込み
3. 命令のデコード
4. レジスタ操作
5. プログラムカウンタのインクリメント
6. 1へ


上部に並んでいる8個の同じパターンが、4ビットのプログラムカウンタと汎用レジスタです。それぞれを操作できますが、可能な操作は代入とインクリメントだけです。

レジスタは2つだけで、一方はプログラムカウンタに使うため、実用的な計算をするのは困難です。命令を追加できる余地は残してあるので、レジスタを追加し、RAMの読み書き命令を実装すれば、実用的な計算にも対応できます。

下部に並んでいるのはプログラムメモリで、8ビット単位で読み出すようになっています。アドレスが4ビットなので、16バイトまで接続できます。今回は8バイトだけ実装しました。

メモリの右側には命令デコーダようの武器ポイントが8ビット分並んでいます。代入とインクリメントだけなので、デコード自体はとても単純です。上部のレジスタの末尾にインクリメントがオーバーフローしたかを記憶する分岐ポイントがつながっています。


### 命令セット

- 0000????: NOP
- 0100????: INC (X += 1)
- 1000????: JMP (PC := X)
- 1010????: JMP (PC := X if overflow==1)
- 1001abcd: LD (X := abcd)
- 1011abcd: LD (X := abcd if overflow==1)

条件付きジャンプはありますが、演算がインクリメントしかないので、前回のインクリメント時にXがオーバーフローしたかどうかだけを判定できます。さらに、ジャンプするにはプログラムカウンタ（PC）に直接即値をセットできず、汎用レジスタを経由しなければならないという残念な仕様です。

## プラレールのシミュレータを作る

CPUの設計やテストに使えそうなプラレールのエディタやシミュレータがなかったため、作成しました。

- https://binzume.github.io/plarail-sim/ ([GitHub](https://github.com/binzume/plarail-sim))

静的なhtmlとjsだけなので、リポジトリをcloneしてindex.htmlを開くだけでも動作します。
この記事のCPUのレイアウトもexamples内にあります。

描画のパフォーマンスがあまり良くないため、1万レールを超えるレイアウトでは操作がもたつきます。複雑なレイアウトを快適に編集するには、以下のテクニックが有効です。

- Vキーを押すと、選択レールと未接続レール以外が一時的に非表示になります。編集したい範囲だけを表示できます
- 階層を分けて、1F、2F……のようにフィルタして表示します
- モジュールごとにレイアウトを作成し、複数ファイルをドロップまたはSHIFT＋ドロップしてレイアウトをマージします
- `cmds` 以下にあるコマンドラインシミュレータには、レール通過時にログを出す機能があります。プラレールのテストを書くのに便利です

## プラレール上で計算を行う

プラレールで計算機を作りたいと夢見る人は世の中にたくさんいるので、探せば分かりやすい解説が見つかります。以下のリンク先の説明がとても分かりやすいので、事前に読んでおくと理解しやすいと思います。

- [プラレールで半加算器を設計した話](https://cybozushiki.cybozu.co.jp/articles/m001205.html)

最近、「[自動ターンアウトレール](https://takaratomymall.jp/shop/g/g4904810150985/)」という便利なレールを知りました。これがあれば計算できると考えて検索したところ、先人がいました。


### 基本素子

基本的には分岐ポイントを組み合わせて、半導体の論理回路のようなものを作っていきます。
ただし、公式のレールだけでは複数の列車を同期させる仕組みを作れません。そのため、列車の速度に依存せず確実に動作させるには、1つの列車で一筆書きできる回路を設計する必要があります。

#### ポイント切り替え

ターンアウトレールや単線複線ポイントレールを使います。

プラレールの分岐ポイントは、分岐先側から列車が進入すると向きが切り替わるため、読み書きが可能なレジスタとして使えます。

分岐の組み合わせによって0/1のどちらかのレールにたどり着くように線路を接続し、論理回路を作ります。


### 自動ターンアウトレール

列車の向かう先を交互に振り分けたり、方向を固定したりする設定を持つレールです。

この自動ターンアウトレールには、もう1つ重要な特性があります。逆向きに進入しても、ポイントの状態が変わりません。一見なんてことのない性質ですが、通常の分岐ポイントでは（通常の使い方では）実現できません。

ただ、プラレールにはまったことがあるなら、通常の切り替えポイントの黄色いパーツを外して切り替わらないようにしたり、輪ゴムやテープなどで決めた状態に固定して使ったりしたことがある人も多いはずです（絶対欲しくなるのに、なぜ製品化されていないのでしょう？）。

今回は、自動切り替え動作のものを赤、固定動作のものを緑のレールとして表示しています。

## プラレール論理回路

### NAND

まずは基本のNANDゲートです。これは簡単です。

![image.png](https://qiita-image-store.s3.ap-northeast-1.amazonaws.com/0/58515/dc73fbca-a97f-47c6-9b6a-d6343b0746b0.png)

少しずるをしていて、緑色のレールは切り替えポイントを固定し、逆側から列車が進入しても状態が変わらないようにしています。


シミュレータは高架も扱えるようにしましたが、レールの衝突判定をしていないため、回路は平面で作っています。

上の画像では、各入力の書き込みに使った列車を使い捨てる、富豪的な配置にしています。しかし実際には、回収用の分岐から列車を取り出して次の回路に向かわせ、1つの列車だけで動かす必要があります。

### 値の複製

電子回路なら配線をつなぐだけで信号を分岐させられますが、列車は分裂しないので、一筆書きで計算しなければなりません。そのため、NANDゲートだけでは足りません。

![image.png](https://qiita-image-store.s3.ap-northeast-1.amazonaws.com/0/58515/c4b58a8b-dcf6-440e-88bf-a15d2187e862.png)

同じ分岐ポイントから2回読み出し、自動ターンアウトレールで1回目と2回目の行き先を変えています。

内部の切り替えポイントの初期状態を注意深く設定すれば、特殊なレールがなくても実現できます。しかし、実行前に状態をリセットする必要があり不便なので、リンク先と同じ仕組みにしました。

### 複数箇所からの書き込み

読み出しと同様に、書き込み時にも列車自身はどこから来たのかを忘れてしまうため、レールの状態で保持しておく必要があります。


### プログラムメモリ

プログラムメモリは、ポイント切り替えレールを並べて実装します。
プログラムからの動的な書き換えはサポートしません。

![image.png](https://qiita-image-store.s3.ap-northeast-1.amazonaws.com/0/58515/f0a15076-9200-41cd-93bb-03fda0a561f3.png)

8ビット ×（0または2）の16本のレールをメモリバスとして扱います。
一番上の分岐に格納されている値がLSBです。

1ビットずつ順番に読み込みますが、8ビット単位で扱い、読み出し順序も重要ではないため、自動ターンアウトレールをツリー状に並べます。
この場合、LSB=1、MSB=8として、1、5、3、7、2、6、4、8という順序で読み出されます。そのため、8ビット目に列車が来た時点で命令のデコードを始めるようになっています。


### レジスタの設計

上に書いた通り、レジスタの書き込み・読み出し経路数に比例して規模が大きくなるため、ファンイン・ファンアウト数をなるべく小さくする必要があります。そのため、レジスタに対する操作を考慮しながらレジスタを構成する各ビットを設計します。

今回はインクリメントと代入だけなので、レジスタの各ビットに以下の入出力を設けます。

- 入力: INC, COPY
- 代入用ソースレジスタからの入力: 0、1

- 操作: 次ビットへ
- EXIT

インクリメントは繰り上がりがなければ途中で終了できるので、EXITを設けています。
今回は4ビットですが、並べれば任意のビット数に拡張できるように設計します。

COPY動作では、左上にある切り替えポイントの値を内部に取り込みます。

![image.png](https://qiita-image-store.s3.ap-northeast-1.amazonaws.com/0/58515/374a79e9-5cac-4aa9-ad86-746c48b1964d.png)

これで1ビット分です。320レールほどあります。

## 動作確認

シミュレータはブラウザ上では16倍速までしか設定が無く時間がかかります。
なので、コマンドライン版のシミュレータでテストします。
インスペクタでレールのイベントに何か書いておくと、シミュレータ上でのレール通過時にログを出せます。

```
node cmds/simulate.js examples/cpu/cpu.json --speed 1000
```
