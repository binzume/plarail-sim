# プラレールによる計算の実行

## 素子の記述

### 内部接続

以下に示す各行は、素子内部のレール接続を表す。
- 入力レール => 出力レール の関係
- `I_0, I_1 => DONE (write)`：`I_0` または `I_1` のレールから入った列車は内部状態を変え、`DONE` レールから出る
- `READ => O_0, O_1`：`READ` から入った列車は、内部状態により `O_0` または `O_1` のどちらかから出る

`=>` の右辺が複数ある場合は分岐を表す。列車は内部状態に応じて、右辺のうち1本だけを選択して進む。
`(write)` は内部状態を変える可能性がある接続を表し、その変更が以降の分岐に影響することがある。
`(write)` のない接続は読み出しであり、`READ` であることは明記しない。

端子名は素子の論理的な役割を表す。複合素子を構成するときは、同じ役割を持つ端子の名前を、構成先の仕様に合わせて読み替えてよい。
また、構成に使用しない端子は未接続のままにしてよい。
内部接続に明記されていない逆方向の走行については、仕様上は未定義とする。

### 実行モデル

- 列車は常に1台だけ使用する。
- 列車は入力値・経路履歴・分岐元などの論理情報を保持しない。
- 1回の内部接続の実行は、1台の列車が連続した1本の経路を走る一筆書きとして行う。
- 列車を複製したり、複数の経路を同時に走行させたりしてはならない。
- 分岐では列車は1本の経路だけを選択する。分岐した複数の経路を同じ処理で並行して通過することはできない。
- 複数の読み出しポートを使用する場合は、1台の列車が順番に通過できるよう、経路を接続しておく必要がある。
- 複数の経路が1本のレールに合流した場合、合流後の列車からは、どの経路から来たかを判別できない。

# 基本素子

## JOIN

動作: A, B を Cに合流させる。逆向きに入った場合は A から脱出

内部接続:

- A, B => C
- C => A

PARTS: turnout-a または turnout-b のmodeを fixed にして利用。

## SWITCH

動作: O=I (1ビットのレジスタ)

内部接続:

- O_0, O_1 => I (write)
- I => O_0, O_1

PARTS: single-double-point-a または single-double-point-b を使う

## AUTO_SWITCH

動作： Iから列車が入るたびに交互に O_0, O_1 に出口が変わる。初期状態ではO_0とする。

- I => O_0, O_1 (write)
- O_0, O_1 => I

PARTS: turnout-a または turnout-b のmodeを auto にして利用。

# 複合素子

## REG

動作: SWITCHの読み出しと書き込みを分離した素子

内部接続:

- I_0, I_1 => DONE (write)
- READ => O_0, O_1

### SWITCHとJOINからの構成

SWITCHを1個、JOINを3個使用するとREGを構成できる。
SWITCHを `S` とし、JOINを次のように接続する。

| JOIN | A | B | C |
| --- | --- | --- | --- |
| `J_R` | `DONE` | `READ` | `S.I` |
| `J_0` | `O_0` | `I_0` | `S.O_0` |
| `J_1` | `O_1` | `I_1` | `S.O_1` |

このとき、定義された順方向の経路は次のようになる。

```text
I_0  => S.O_0 => S.I => DONE (write)
I_1  => S.O_1 => S.I => DONE (write)

READ => S.I => S.O_0 => O_0   (Sの状態が0の場合)
READ => S.I => S.O_1 => O_1   (Sの状態が1の場合)
```

したがって、REGの書き込み・読み出し定義と一致する。
出力端子からの逆方向の走行など、上記に明記されていない経路は未定義とする。


## DUP

動作: A=O=I

内部接続:
- I_0 => O_0 (write)
- I_1 => O_1 (write)
- READ_A => A_0, A_1

### JOIN、SWITCH、AUTO_SWITCHからの構成

`DUP` は、2個の `REG`、2個の `AUTO_SWITCH`、7個の `JOIN` で構成できる。
各 `REG` は、上で示した `SWITCH` 1個と `JOIN` 3個による構成を使用するため、
基本素子まで展開すると次の個数になる。

- `SWITCH`：2個
- `JOIN`：`REG`内部の6個と合流用の1個、合計7個
- `AUTO_SWITCH`：2個

2個の `REG` を次のように呼ぶ。

- `R_S`：書き込み値を保持するソース
- `R_A`：`A_0`, `A_1` 用のコピー。書き込み中は `O_0`, `O_1` 出力の準備にも使う

2個の `AUTO_SWITCH` を `T_0`, `T_1` とし、それぞれ値0、値1の経路に割り当てる。
`R_S` は1回の書き込み中に2回読み出す。1回目の読み出しで `R_A` を更新し、
2回目の読み出しで `O_0` または `O_1` へ出力する。接続は次の通りである。
`READ_A` が最初の書き込みより先に使用される場合にも一致するよう、`R_S` と `R_A`
は同じ初期値にしておく。`T_0` と `T_1` の初期状態は定義通り `O_0` とする。

| 接続元 | 接続先 | 用途 |
| --- | --- | --- |
| `I_0` | `R_S.I_0` | 値0を書き込む |
| `I_1` | `R_S.I_1` | 値1を書き込む |
| `R_S.DONE` | `J_D.A` | ソース書き込み完了 |
| `R_A.DONE` | `J_D.B` | コピー完了 |
| `J_D.C` | `R_S.READ` | ソースを再び読む |
| `R_S.O_0` | `T_0.I` | 値0の出力先を交互に選ぶ |
| `R_S.O_1` | `T_1.I` | 値1の出力先を交互に選ぶ |
| `T_0.O_0` | `R_A.I_0` | 1回目に値0をコピーする |
| `T_0.O_1` | `O_0` | 2回目に値0を出力する |
| `T_1.O_0` | `R_A.I_1` | 1回目に値1をコピーする |
| `T_1.O_1` | `O_1` | 2回目に値1を出力する |
| `READ_A` | `R_A.READ` | `A` 用コピーを読む |
| `R_A.O_0` | `A_0` | 読み出し値0を出力 |
| `R_A.O_1` | `A_1` | 読み出し値1を出力 |

`J_D` は次の `JOIN` である。

| JOIN | A | B | C |
| --- | --- | --- | --- |
| `J_D` | `R_S.DONE` | `R_A.DONE` | `R_S.READ` |

### 書き込み経路の確認

例えば `I_0` から入った場合、`R_S` に0を書き込み、`R_S` を2回読み出す。
1回目の読み出しでは `T_0` の初期状態により `R_A` へ進み、2回目では
`T_0` が切り替わって `O_0` へ進む。

```text
I_0
  => R_S.I_0 => R_S.DONE => J_D.C => R_S.READ
  => R_S.O_0 => T_0.I => T_0.O_0 => R_A.I_0 => R_A.DONE
  => J_D.C => R_S.READ
  => R_S.O_0 => T_0.I => T_0.O_1 => O_0
```

`I_1` の場合も同じ経路で、`T_1` と値1の端子を通る。

```text
I_1
  => R_S.I_1 => R_S.DONE => J_D.C => R_S.READ
  => R_S.O_1 => T_1.I => T_1.O_0 => R_A.I_1 => R_A.DONE
  => J_D.C => R_S.READ
  => R_S.O_1 => T_1.I => T_1.O_1 => O_1
```

各 `AUTO_SWITCH` は1回の書き込み中に必ず2回通過する。したがって、初期状態の
`O_0` から始まり、1回目は `O_0`、2回目は `O_1` を選び、その後は次の書き込みに
備えて初期状態の `O_0` に戻る。値0と値1のどちらを書き込んでも、使用した
`AUTO_SWITCH` は2回通過するため、書き込み値が変化しても動作する。

### 読み出し経路の確認

書き込み後は `R_A` が書き込み値を保持する。

```text
READ_A => R_A.READ => R_A.O_0 => A_0   (値が0の場合)
READ_A => R_A.READ => R_A.O_1 => A_1   (値が1の場合)
```

以上により、`I_0 => O_0`、`I_1 => O_1`、`READ_A => A_0, A_1` が成立する。
`AUTO_SWITCH` の状態は各書き込みで2回切り替わって初期状態へ戻るため、書き込み値の
系列には依存しない。列車は常に1台で、各経路を順番に通過する。



## NAND

O = !(A and B)

内部接続:

- A_0, A_1 => DONE_A (write)
- B_0, B_1 => DONE_B (write)
- READ => O_0, O_1

## XOR

O = A xor B

内部接続:
- A_0, A_1 => DONE_A (write)
- B_0, B_1 => DONE_B (write)
- READ => O_0, O_1 

# MODULES

## Nビットカウンタ

`N`個のビット状態を共有し、`2^N`を法としてインクリメントとデクリメントを行う。
ビット状態は `b_0` が最下位ビット、`b_{N-1}` が最上位ビットである。

このカウンタでは、列車がINCまたはDECという情報を保持することを前提にしない。
各ビットセルにモード保持用の `REG` `M_i` を置き、INCなら1、DECなら0を書き込む。
このモードは、ビット状態 `S_i` の書き込みが終わった後に読み出して、INC用または
DEC用の読み出し経路を選ぶために使う。

重要なのは、ビット状態を保持する `S_i` の書き込み完了を、入力経路によって
`WRITE_DONE_INC` と `WRITE_DONE_DEC` に分けようとしないことである。`S_i` が裸の
`SWITCH` である限り、どの経路から書き込まれたかは `S_i` の出口から判別できない。
書き込み完了は常に1本の `STATE_WRITE_DONE` とし、モードは `M_i` から明示的に
読み出す。

`S_i` の読み出しには、更新前の反転処理用、更新後のINC判定用、更新後のDEC判定用の
3つの論理的な読み出しコンテキストを用意する。これは列車を複製するという意味では
なく、同じ状態への経路を合流させずに接続するという意味である。裸の `SWITCH` には
1つのREAD経路しかないため、この3コンテキスト部分は `DUP`、`SWITCH`、`JOIN` から
構成する共有状態アクセスとして別途実装する必要がある。

### カウンタ全体の入出力

| 入力 | 接続先 | 動作 |
| --- | --- | --- |
| `INC` | `b_0.INC_IN` | `M_0` に1を書き込み、INCを開始する |
| `DEC` | `b_0.DEC_IN` | `M_0` に0を書き込み、DECを開始する |

| 出力 | 意味 |
| --- | --- |
| `INC_DONE` | INCが完了した。最上位ビットからの桁上がりは捨てる |
| `DEC_DONE` | DECが完了した。最上位ビットからの借りは捨てる |

`INC` と `DEC` の両方が同時に入力されることはない。各ビットの処理は1台の列車が
順番に行うため、あるビットの書き込みが完了してから、そのビットの更新後の値を
読み出す。したがって、読み出し経路と書き込み経路が同時に競合することはない。

### ビットセル `b_i`

各ビットセルは、ビット値を保持する `S_i` と、モードを保持する `M_i` からなる。

- `S_i`：ビット値を保持する1個の共有状態
- `M_i`：INC/DECを保持する1ビットの `REG`。1がINC、0がDEC
- `INC_IN`：INC処理の入力
- `DEC_IN`：DEC処理の入力
- `INC_NEXT`：INCで次のビットへ進む出力
- `INC_DONE`：INCをこのビットで終了する出力
- `DEC_NEXT`：DECで次のビットへ進む出力
- `DEC_DONE`：DECをこのビットで終了する出力

内部には、同じ `S_i` に対する次のコンテキスト別ポートを用意する。
これらは物理的な状態を複製するものではなく、同じ状態への読み書き経路を合流させず
に区別するための論理的な端子名である。

| 内部ポート | 用途 | 出力の意味 |
| --- | --- | --- |
| `READ_TOGGLE` | 更新前の `S_i` を読み、反転値を書き込む | `TOGGLE_0`, `TOGGLE_1` |
| `INC_CHECK` | INCで書き込み後の `S_i` を読む | `INC_CHECK_0`, `INC_CHECK_1` |
| `DEC_CHECK` | DECで書き込み後の `S_i` を読む | `DEC_CHECK_0`, `DEC_CHECK_1` |
| `SET_0` | `S_i` に0を書き込む | `STATE_WRITE_DONE` |
| `SET_1` | `S_i` に1を書き込む | `STATE_WRITE_DONE` |

`S_i` の書き込み完了は、INCとDECで共通の `STATE_WRITE_DONE` である。`S_i` の
`I` から出たレールを、入力経路に応じて `WRITE_DONE_INC` と `WRITE_DONE_DEC` に
分岐させることはできない。合流後の列車は、どの入力経路から来たかを保持しないため
である。

`S_i` の状態分岐と書き込み先の対応は次の通りである。`SET_0` と `SET_1` は
セルの外から入力する端子ではなく、`S_i` の `O_0` と `O_1` へ入る内部レールを表す。

| 分岐元 | `S_i` への接続 | `S_i` からの出口 | 意味 |
| --- | --- | --- | --- |
| `TOGGLE_0` | `S_i.O_1` | `STATE_WRITE_DONE` | 更新前が0なので1を書き込む |
| `TOGGLE_1` | `S_i.O_0` | `STATE_WRITE_DONE` | 更新前が1なので0を書き込む |

書き込み後の `S_i` の読み出しは、処理コンテキストごとに次のように接続する。

| 読み出し入力 | 状態0の出口 | 状態1の出口 |
| --- | --- | --- |
| `INC_CHECK` | `INC_CHECK_0` | `INC_CHECK_1` |
| `DEC_CHECK` | `DEC_CHECK_0` | `DEC_CHECK_1` |

`STATE_WRITE_DONE` から `M_i.READ` に入り、`M_i` の状態0/1によって `DEC_CHECK`/
`INC_CHECK` を選ぶ。つまり、セルの外部から列車が入る入力は `INC_IN` と `DEC_IN`
の2つだけであり、セルの外部へ出る出口は `INC_NEXT`、`INC_DONE`、`DEC_NEXT`、
`DEC_DONE` の4つである。`READ_TOGGLE`、`INC_CHECK`、`DEC_CHECK`、`M_i.READ` は
セル内部の経路を分けるための論理ポートである。

### INCの全経路

`INC_IN` に入った列車は、まず現在値を読み、反転した値を書き込む。
最初に `M_i.I_1` に入り、`M_i.DONE` から共通の `READ_TOGGLE` へ進む。その後、
`M_i` を読み直してINCの判定経路を選び、`INC_CHECK` で書き込み後の値を読む。
値が0なら次のビットへ進み、値が1なら完了する。

```text
INC_IN
  => M_i.I_1 => M_i.DONE => READ_TOGGLE
  => TOGGLE_0 => SET_1 => STATE_WRITE_DONE => M_i.READ => M_i.O_1
       => INC_CHECK => INC_CHECK_1 => INC_DONE
  => TOGGLE_1 => SET_0 => STATE_WRITE_DONE => M_i.READ => M_i.O_1
       => INC_CHECK => INC_CHECK_0 => INC_NEXT
```

上の2行は `READ_TOGGLE` と `M_i.READ` の状態分岐を表す。実際には、現在値が0または1のどちらか
一方の経路だけを列車が通過する。

| 更新前 | 書き込み | 更新後 | 次の出口 |
| --- | --- | --- | --- |
| 0 | `SET_1` | 1 | `INC_DONE` |
| 1 | `SET_0` | 0 | `INC_NEXT` |

### DECの全経路

`DEC_IN` に入った列車も現在値を反転する。ただし、`DEC_CHECK` で値が1なら次の
ビットへ進み、値が0なら完了する。DECでは最初に `M_i.I_0` に入り、書き込み後に
`M_i.O_0` から `DEC_CHECK` へ進む。

```text
DEC_IN
  => M_i.I_0 => M_i.DONE => READ_TOGGLE
  => TOGGLE_0 => SET_1 => STATE_WRITE_DONE => M_i.READ => M_i.O_0
       => DEC_CHECK => DEC_CHECK_1 => DEC_NEXT
  => TOGGLE_1 => SET_0 => STATE_WRITE_DONE => M_i.READ => M_i.O_0
       => DEC_CHECK => DEC_CHECK_0 => DEC_DONE
```

| 更新前 | 書き込み | 更新後 | 次の出口 |
| --- | --- | --- | --- |
| 0 | `SET_1` | 1 | `DEC_NEXT` |
| 1 | `SET_0` | 0 | `DEC_DONE` |

### ビットセル間の接続

最下位ビットから最上位ビットへ、INCとDECのレールをそれぞれ接続する。

```text
INC => b_0.INC_IN
b_0.INC_NEXT => b_1.INC_IN
b_1.INC_NEXT => b_2.INC_IN
...
b_{N-2}.INC_NEXT => b_{N-1}.INC_IN
b_{N-1}.INC_NEXT => INC_DONE

DEC => b_0.DEC_IN
b_0.DEC_NEXT => b_1.DEC_IN
b_1.DEC_NEXT => b_2.DEC_IN
...
b_{N-2}.DEC_NEXT => b_{N-1}.DEC_IN
b_{N-1}.DEC_NEXT => DEC_DONE
```

最上位ビットで `INC_NEXT` または `DEC_NEXT` に到達した場合は、桁上がりまたは
借りを捨てて完了する。これが `2^N` を法とするラップアラウンドである。

### 1ビットあたりの構成上の注意

1個の `SWITCH` を単純に読み書きへ接続しただけでは、次の2点を同時に満たせない。

1. 同じ状態を、更新前と更新後の両方で読むこと
2. 更新後にINC用とDEC用の読み出し経路を分けること

そのため、各ビットでは `S_i` の読み出しに `READ_TOGGLE`、`INC_CHECK`、
`DEC_CHECK` の3つの論理コンテキストを設ける。また、INC/DECの情報を経路の合流後も
使えるように、`M_i` に明示的に保存する。`STATE_WRITE_DONE` の後で `M_i.READ` を
通ることで、列車の来歴ではなく、保持された状態に基づいて判定経路を選べる。

この構成で必要な「同じ `S_i` に対する複数の読み出しコンテキスト」は、現在の
`DUP`、`SWITCH`、`JOIN` から構成する共有状態アクセスとして別途定義する必要がある。
ただし、そのアクセスの出口を `S_i` の書き込み出口から直接INC/DECに分けることは
しない。`S_i` の書き込み出口は常に1本であり、モードの選択は `M_i.READ` が担う。

この構成では、各ビットで必ず「読み出し、反転値の書き込み、書き込み後の読み出し」
を行う。従って、桁上がりまたは借りが止まる場合でも、処理時間はビット数 `N` に
比例し、最悪時の時間計算量は `O(N)` である。各ビットの `S_i` と `M_i` が状態を
保持するため、状態を保持する論理素子は2個ずつ、全体で `2N` 個となり、状態規模は
`O(N)` である。

## MEM

メモリ。アドレス幅がNビットの場合、読み書きにかかる時間はO(N^2)。

内部接続:
- W_ADDR1_0, W_ADDR1_1 => W_ADDR1_DONE (write)
- W_ADDR2_0, W_ADDR2_1 => W_ADDR2_DONE (write)
- W_ADDRx_0, W_ADDRx_1 => W_ADDRx_DONE (write)
- W_DATA_0, W_DATA_1 => W_DONE (write)

- R_ADDR1_0, R_ADDR1_1 => R_ADDR1_DONE (write)
- R_ADDR2_0, R_ADDR2_1 => R_ADDR2_DONE (write)
- R_ADDRx_0, R_ADDRx_1 => R_ADDRx_DONE (write)
- R => R_DATA_0, R_DATA_1
